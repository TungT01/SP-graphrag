# SP-GraphRAG 实验报告 v7

**结构熵约束 GraphRAG（Structural-entropy Penalized GraphRAG）**

> 实验日期：2026-04-28
> 数据集：MultiHop-RAG（609 篇文章，2556 条 QA）
> 评估规模：200 QA 抽样（169 条有效，涉及 163 篇文章）
> 实体规模：13,716 个实体，18,044 条关系

## 1. 研究背景与动机

标准 GraphRAG 使用 Leiden 算法对知识图谱做层次社区检测，目标函数为纯模块度 Q 最大化。这种做法忽略了文本的物理边界信息——一篇文章、一个段落、一个句子构成天然的语义单元，但 Leiden 可以在模块度驱动下任意地将来自不同物理单元的节点合并到同一社区，破坏文本的物理完整性。

SP-GraphRAG 的核心思想是在 Leiden 的目标函数中引入**结构熵惩罚项**：

$$J = Q_{\text{leiden}} - \lambda \cdot H_{\text{structure}}$$

其中 $H_{\text{structure}} = -\sum_i p_i \log p_i$ 衡量社区内节点跨物理单元的分散程度。$\lambda$ 越大，算法越倾向于保持物理边界。通过退火策略（AnnealingSchedule）在层次上递减 $\lambda$，实现「低层保持物理纯净、高层允许跨文档合并」的渐进式聚合。

## 2. 核心问题与修复历程

### 2.1 根因链：为什么结构熵恒为零

实验初期发现 $H \equiv 0$，无论 $\lambda$ 取何值，结构熵约束都不起作用。经过系统诊断，定位到一条完整的根因链：

**(1) node_id 设计导致同名实体在不同句子中成为不同节点。** 实体抽取时 `node_id = f"{sent_id}-{title_norm}"`，例如 "Apple" 在句子 0 和句子 1 中分别生成 `doc1-p0-s0-apple` 和 `doc1-p0-s1-apple` 两个独立节点。

**(2) 所有边（共现 + 三元组）均为句内边。** 因为共现和三元组都在单个句子内抽取，边的两端 node_id 必然共享同一个 sent_id。

**(3) 图退化为「句内孤岛森林」。** 每个连通分量恰好是单个句子内的节点组成的子图，不同句子之间完全不连通。

**(4) 每个连通分量内所有节点共享同一个 para_id，结构熵恒为零。** 因为 $H = -\sum p_i \log p_i$，当所有 $p_i$ 集中在同一个物理单元时 $H = 0$。于是 $\lambda \times 0 = 0$，约束彻底失效。

### 2.2 修复方案：EdgeSchedule + 权重校准

**EdgeSchedule（分层加边调度器）** 在 Leiden 的 Level 0 阶段一次性注入三类同名实体边，打破句内孤岛：

| 边类型 | 匹配条件 | 默认权重 | 连接方式 |
|---|---|---|---|
| 同段落跨句子 | 同 para_id + 不同 sent_id + 同名实体 | 2.0 | 链式 |
| 同文档跨段落 | 同 doc_id + 不同 para_id + 同名实体 | 1.5 | 代表节点链式 |
| 跨文档 | 不同 doc_id + 同名实体 | 1.0 | 代表节点链式（上限 5） |

**权重校准**的关键考量：原始图总边权 $m \approx 18{,}000$，Leiden 的模块度增益 $\delta Q \approx w / m$。若注入边权重 $w = 0.2$，则 $\delta Q \approx 1.1 \times 10^{-5}$。而结构熵变化 $\delta H \approx \ln 2 \approx 0.693$，即使 $\lambda = 0.001$，$\lambda \cdot \delta H \approx 6.9 \times 10^{-4}$ 仍远大于 $\delta Q$，阻止所有跨段落合并。因此必须将边权重提高到 1.0 以上，使 $\delta Q$ 和 $\lambda \cdot \delta H$ 在同一量级上博弈。

### 2.3 评估 Bug 修复：top-down ID 粒度不匹配

在 v6 实验中观察到 P@5 对 EdgeSchedule 组退化了约 22%，一度怀疑是社区结构变化导致的检索质量下降。深入诊断发现这是**评估代码的 bug**：

top-down 检索路径从社区的 `text_unit_ids` 字段取 ID，这些 ID 是句子级格式（如 `"Article Title-p006-s000"`），而 ground-truth 是文章标题（如 `"Article Title"`）。两者永远无法匹配，top-down 对评估指标贡献为零，但其 sent_id 插入检索结果列表后挤占了 bottom-up 有效命中的位置。EdgeSchedule 组的社区更大、层次更深，产生了更多无效 sent_id，稀释更严重。

修复方案：优先使用社区的 `doc_ids` 字段（文档级 ID），无则从 sent_id 中正则提取 doc_id（去掉 `-pNNN-sNNN` 后缀）。修复后 P@5 退化从 -22.2% 降至 +0.0%。

## 5. 关键发现

### 发现 1：结构熵约束已完全生效

结构熵从 Baseline 的恒 0 提升到 0.10–0.17 区间，$\lambda$ 与 $H$ 呈明确的负相关关系：

$$\lambda = 0 \Rightarrow H = 0.1374 \quad;\quad \lambda = 0.001 \Rightarrow H = 0.1152 \quad;\quad \lambda = 0.003 \Rightarrow H = 0.1045$$

$\lambda$ 从 0 增加到 0.003 时，结构熵下降了 24%，验证了目标函数 $J = Q - \lambda H$ 确实在引导 Leiden 偏好低熵（物理纯净的）社区划分。

### 发现 2：结构熵约束对检索质量几乎无损

在 200 QA（169 valid）规模下，所有 EdgeSchedule 组的检索指标波动均在 ±2.5% 以内。最佳组 [3]（$\lambda = 0.003$）的 P@5 与 Baseline 完全持平（+0.0%），Recall@5 微升 +0.6%，MRR 仅降 0.5%。这意味着**可以在不牺牲检索质量的前提下，显著增强社区的物理纯净性**。

### 发现 3：先前观察到的 P@5 退化是评估 Bug

v6 实验中 EdgeSchedule 组 P@5 退化 22% 的「发现」实为评估代码的 ID 粒度不匹配 bug。修复 `evaluator.py` 中 top-down 路径的 ID 提取逻辑后，退化完全消失。这一教训提醒我们：在对照实验中，评估代码的公平性与正确性同样需要严格验证。

### 发现 4：跨文档边增加多样性但边际收益递减

[5] 组注入了 4,469 条边（vs [1] 的 2,370 条），社区层次从 8 增到 11，平均社区大小从 3.24 增到 4.62，结构熵最高（0.1682）。但 MRR 下降了 1.6%，NDCG@10 下降了 2.5%。跨文档同名实体合并在当前 TF-IDF 检索框架下的贡献有限，需要语义向量检索来充分发挥其价值。

### 发现 5：Path A 的增量贡献不显著

[4]（+PathA）相比 [2] 没有带来明显改善，反而模块度从 0.7995 降到 0.7883（-1.4%）。Path A 的文档内全连接边打破了 Leiden 的模块度优化路径，但未在检索质量上获得补偿。EdgeSchedule 的链式连接策略已足够，Path A 可作为可选功能保留。

## 7. 技术架构概览

```
Input Documents
       │
       ▼
  ┌─────────────┐
  │  Ingestion   │  doc → paragraphs → sentences (SentenceUnit)
  │  (spaCy/正则) │  para_id = {doc_id}-p{NNN}
  └──────┬──────┘  sent_id = {para_id}-s{NNN}
         │
         ▼
  ┌─────────────┐
  │  Extraction  │  spaCy NER + 依存三元组
  │  (v2 物理优先)│  node_id = {sent_id}-{title_norm}
  └──────┬──────┘  → entities_df, relationships_df
         │
         ▼
  ┌──────────────────────────────────────────────────┐
  │          Constrained Leiden (SP-GraphRAG)          │
  │                                                    │
  │  Level 0:  EdgeSchedule 注入同名实体边             │
  │            (intra_para=2.0, intra_doc=1.5,         │
  │             cross_doc=1.0)                         │
  │            ↓                                       │
  │  Each Level:                                       │
  │    1. local_moving:  δJ = δQ - λ·δH               │
  │    2. refinement:    受约束的节点重分配             │
  │    3. aggregation:   超节点 + 物理属性聚合          │
  │    4. λ ← anneal(λ)                               │
  │            ↓                                       │
  │  Output: communities_df (多层次社区 + 结构熵)       │
  └──────────────────────┬─────────────────────────────┘
                         │
                         ▼
  ┌─────────────┐   ┌──────────────┐
  │  Top-Down    │   │  Bottom-Up   │   U-Retrieval 双轨融合
  │  社区层次导航  │   │  TF-IDF 物理 │
  │  (全局视角)   │   │  锚点检索     │
  └──────┬──────┘   └──────┬───────┘
         └────────┬────────┘
                  ▼
          merged_context → LLM
```

## 9. 局限性与未来方向

**当前局限**：(1) 检索基于 TF-IDF，语义理解能力有限，跨文档边的价值未被充分挖掘；(2) 实体抽取为 spaCy 规则式，质量受限于 NER 精度；(3) 实验未涉及 LLM 生成质量评估（仅检索阶段）；(4) 169 条有效 QA 的规模下，1-2% 的指标差异可能不具统计显著性。

**未来方向**：(1) 引入向量检索替代 TF-IDF，释放跨文档社区结构的语义潜力；(2) LLM 端到端 QA 评估（生成质量 + 检索质量联合度量）；(3) 动态 $\lambda$ 调整——根据图拓扑特征自适应选择 $\lambda$，而非固定值；(4) 更大规模实验（全量 2556 QA）确认统计显著性。
