## §1 实验背景

### 1.1 项目目标

在 GraphRAG 的社区检测阶段注入结构熵惩罚（目标函数 `J = Q_leiden − λ · H_structure`），使来自同一源文档的实体倾向于聚入同一社区，从而提升多跳问答场景下的检索召回率。

### 1.2 评估数据集

MultiHop-RAG（COLM 2024），609 篇新闻文章，2556 条多跳问答对。问题分为三种类型：`comparison_query`（对比类）、`inference_query`（推理类）、`temporal_query`（时序类）。

### 1.3 评估流程

从 2556 条 QA 中随机采样 200 条（`--n-qa 200`），剔除无法在语料中索引到答案的查询后，剩余 **169 条有效查询**作为评估集。所有方法在相同的 169 条查询上评估，保证可比性。

### 1.4 核心评估指标说明

| 指标 | 全称 | 含义 | 越高越好 |
|---|---|---|---|
| **MRR** | Mean Reciprocal Rank | 第一个正确结果平均排在第几位（的倒数）。MRR=1 表示正确答案总在第 1 位 | ✓ |
| **P@5** | Precision at 5 | 返回的前 5 条结果中有多少比例是正确的 | ✓ |
| **Recall@5** | Recall at 5 | 所有正确结果中有多少比例出现在了前 5 条 | ✓ |
| **NDCG@K** | Normalized Discounted Cumulative Gain | 综合考虑正确结果的排名位置，排得越靠前分越高 | ✓ |
| **模块度 Q** | Modularity | 社区划分质量，社区内部连接密集、社区之间连接稀疏时 Q 高 | ✓ |
| **结构熵** | Structural Entropy | 社区内节点来源分布的信息熵。H=0 表示社区内所有节点来自同一来源 | 看场景 |

## §2 v4 消融实验（唯一已完成的实验）

### 2.1 实验设计

v4 设计了四组消融实验，通过逐步叠加改进来验证每个组件的贡献。

**四组的控制变量关系**：

```
[0] Baseline ──(加入 λ=1000)──→ [1] Ours
                                    │
                              (加入 Path A)
                                    │
                                    ▼
                               [2] Ours+A ──(加入 Path B)──→ [3] Ours+A+B
```

**各组精确配置**：

| 配置项 | [0] Baseline | [1] Ours | [2] Ours+A | [3] Ours+A+B |
|---|---|---|---|---|
| λ_init（结构熵惩罚强度） | **0**（关闭） | **1000** | 1000 | 1000 |
| Path A（文档内消解边） | ✗ | ✗ | **✓** | ✓ |
| Path B（噪声实体过滤） | ✗ | ✗ | ✗ | **✓** |
| anchor_granularity | "sent" | "sent" | "sent" | "sent" |
| EdgeSchedule | ✗ | ✗ | ✗ | ✗ |
| 退火策略 | — | exponential | exponential | exponential |
| 最大层数 | 10 | 10 | 10 | 10 |

> **Path A 是什么**：在图构建阶段，为同一文档内的同名实体按 sent_id 排序后添加链式软连接边（A→B→C），权重 0.5。目的是让跨句子的同名实体有机会被 Leiden 合并到同一社区。对应参数 `intra_doc_merging=True`。
>
> **Path B 是什么**：在实体抽取阶段扩充停用词表（约 60 个噪声词如 "it"、"the report"、"this"），过滤掉 spaCy NER 误识别的功能词/代词/泛指词。效果是实体数从约 60,000 降至约 47,000。对应缓存标签 `full_b`。
>
> **anchor_granularity="sent" 的含义**：每个节点的物理锚点是其所在的句子 ID。由于 v3 架构中每个节点本身就来自唯一一个句子，这导致每个节点的 chunk_id 天然唯一——后续会看到，这让结构熵恒为零。

### 2.3 结果解读（关键发现）

#### 发现一：结构熵惩罚完全未生效

四组实验的 `avg_structural_entropy` 全部为 0.0000，包括逐层的 `entropy_by_level` 也全为零。

**根因**：v4 使用 `anchor_granularity="sent"`，每个节点的物理锚点是其唯一的 sent_id。当社区内每个节点的 chunk_id 各不相同时，结构熵的计算结果趋近于零。目标函数 `J = Q − λ·H` 中的 `λ·H` 项恒为零，λ 从 0 变成 1000 没有任何数学效果——结构熵惩罚从未真正参与社区检测的决策过程。

**这意味着**：v4 中组 [1] 相对组 [0] 的指标改善（P@5 +23.2%）**不是来自结构熵惩罚**，而是来自 λ > 0 时退火机制产生的层次结构变化（1 层→3 层，社区数 22,973→63,497），更多层次 = 更细粒度的社区 = 检索时命中范围更精准。

#### 发现二：Path A 完全无效

组 [1] 和 [2] 的所有指标精确相同——MRR、P@K、Recall@K、NDCG@K、社区数、模块度，没有任何一个数字有差异。

**根因**：Path A 添加的文档内链式边权重为 0.5，远低于句内共现边权重 1.0。在 v3 的碎片化图结构中（约 24,858 个连通分量，最大分量仅 9 个节点），0.5 权重的软连接边太弱，被 Leiden 算法在模块度优化中忽略了。

**这意味着**：仅靠低权重软连接边不足以打破句子级别的图碎片化。v5 因此引入了 EdgeSchedule 分层加边机制，以更系统的方式逐级扩展图的连通性。

#### 发现三：Path B 在本次运行中也无效

组 [2] 和 [3] 的所有指标同样精确相同。

**注意⚠️**：JSON 文件显示四组实验全部使用了相同的数据（47,142 实体 / 61,812 关系），这与实验设计不符——按设计，组 [0][1][2] 应使用原始抽取（约 60,439 实体），组 [3] 才使用噪声过滤后的数据（47,142 实体）。项目早期的手工实验笔记（`ablation_study_notes.md`）中记录的组 [0] 实体数为 60,439、社区数为 29,398，与 JSON 中的 47,142 / 22,973 不一致。**说明 JSON 文件很可能是后续某次运行覆盖了原始结果，四组全部使用了 `full_b` 缓存。**

#### 发现四：与 Naive RAG 差距显著

| 指标 | Our Method 最佳 | Naive RAG | 差距 |
|---|---|---|---|
| MRR | 0.3552 | 0.6389 | 落后 44% |
| P@5 | 0.1633 | 0.2568 | 落后 36% |
| Recall@5 | 0.3230 | 0.5059 | 落后 36% |
| NDCG@5 | 0.2680 | 0.4792 | 落后 44% |

逐句向量化的 Naive RAG 在所有指标上大幅领先基于图的社区检索方法。这并不意外——当结构熵惩罚未生效、图严重碎片化时，社区检索等价于在大量孤立小碎片中做随机匹配，远不如直接对全文做语义相似度检索。

## §3 Naive RAG 基线详情

**来源文件**：`baselines/eval_results/n200/naive_rag_eval_results.json`

### 3.1 方法描述

使用 sentence-transformers（all-MiniLM-L6-v2）将语料逐句向量化，查询时计算余弦相似度，返回 Top-K 最相似的句子作为检索结果。无图结构、无社区、无层次——纯粹的语义向量检索。

### 3.2 整体结果

| 指标 | 数值 |
|---|---|
| MRR | 0.6389 |
| P@1 | 0.4911 |
| P@3 | 0.3491 |
| P@5 | 0.2568 |
| P@10 | 0.1538 |
| Recall@5 | 0.5059 |
| Recall@10 | 0.5976 |
| F1@5 | 0.3356 |
| NDCG@5 | 0.4792 |
| NDCG@10 | 0.5216 |
| 有效查询数 | 169 |
| 平均延迟 | 70.6ms |
| 平均上下文 token 数 | 385 |

### 3.3 按问题类型细分

| 问题类型 | 数量 | MRR | Recall@5 | 说明 |
|---|---|---|---|---|
| comparison_query | 57 | **0.7143** | **0.6520** | 对比类问题，Naive RAG 最擅长 |
| inference_query | 59 | 0.6193 | **0.3475** | 多跳推理，Recall 明显下降 |
| temporal_query | 53 | 0.5796 | 0.5252 | 时序类问题，表现居中 |

> **关键观察**：inference_query 的 Recall@5 仅 0.3475，远低于其他两类（0.65 / 0.53）。这说明逐句向量检索在需要跨文档推理的场景下有天然短板——正是 GraphRAG 方法最有希望超越 Naive RAG 的突破口。如果 v5 的结构熵惩罚能有效工作，应该优先在 inference_query 上拉开差距。

## §5 v5 实验（代码已就绪，尚未运行）

### 5.1 设计目标

v5 针对 v4 暴露的三个根本缺陷设计了修复方案：

| 缺陷 | v4 表现 | v5 修复 |
|---|---|---|
| 结构熵恒为零 | `anchor_granularity="sent"` → H ≡ 0 | 改为 `"para"` → 同段落节点共享 chunk_id → H > 0 |
| 图严重碎片化 | ~24,858 个连通分量，最大 9 节点 | EdgeSchedule 分 3 级注入跨句/跨段/跨文档边 |
| λ 控制层数而非合并节奏 | `lambda < 1e-6` 终止条件导致 λ 衰减后提前停止 | 移除该终止条件，改用收敛判定 |

### 5.2 六组消融设计

**来源**：`experiments/run_multihop_eval.py` L493-L542

```
[0] Baseline          [1] 仅改锚点         [2] 仅分层加边
 λ=0, sent, 无ES       λ=1000, para, 无ES    λ=1000, sent, ES(无跨文档)
     │                      │                      │
     │    对比：锚点粒度影响   │    对比：两者叠加效果     │
     │          ┌────────────┘          ┌────────────┘
     ▼          ▼                       ▼
            [3] 锚点+分层加边
             λ=1000, para, ES(无跨文档)
                    │
              (加入 Path A)
                    │
                    ▼
            [4] 完整方案+PathA
             λ=1000, para, ES(无跨文档), PathA(w=0.5)
                    │
             (开启跨文档边)
                    │
                    ▼
            [5] 完整方案+跨文档
             λ=1000, para, ES(含跨文档), PathA(w=0.5)
```

**各组精确参数**：

| 参数 | [0] | [1] | [2] | [3] | [4] | [5] |
|---|---|---|---|---|---|---|
| λ_init | 0 | 1000 | 1000 | 1000 | 1000 | 1000 |
| anchor_granularity | sent | **para** | sent | **para** | **para** | **para** |
| use_edge_schedule | ✗ | ✗ | **✓** | **✓** | **✓** | **✓** |
| edge_schedule_cross_doc | — | — | ✗ | ✗ | ✗ | **✓** |
| intra_doc_merging (Path A) | ✗ | ✗ | ✗ | ✗ | **✓** (w=0.5) | **✓** (w=0.5) |
| 退火策略 | — | exp | exp | exp | exp | exp |
| decay_rate | — | 0.5 | 0.5 | 0.5 | 0.5 | 0.5 |

**消融逻辑**：

- [0] → [1]：验证 **锚点粒度从 sent 改为 para** 的单独效果——结构熵是否变得非零？
- [0] → [2]：验证 **分层加边** 的单独效果——图碎片化是否缓解？
- [1] + [2] → [3]：验证两个修复 **叠加** 的效果
- [3] → [4]：验证在新架构上 **Path A** 是否有增益（v4 中无效，v5 中呢？）
- [4] → [5]：验证 **跨文档边** 的增量价值（代价是可能引入噪声）

### 5.3 运行命令

```bash
cd /path/to/graphrag_improved
python -m experiments.run_multihop_eval --n-qa 200 --use-spacy --groups 0,1,2,3,4,5
```

### 5.4 v5 冒烟测试已通过的验证点

`smoke_v5.py` 在小规模构造数据上已验证：

1. EdgeSchedule.build() 能正确生成三级分层边
2. `anchor_granularity="para"` 时同段落节点确实共享 chunk_id
3. 结构熵在 para 粒度下不再恒为零（H > 0）
4. λ > 0 时结构熵确实低于 λ = 0 时（惩罚项在起作用）
5. 所有原始节点在每层都有社区分配，无提前终止

> 冒烟测试通过证明 v5 的三个修复在算法层面是正确的。但在真实数据集（47,142 实体、609 篇文章）上的实际检索效果，需要跑完六组实验才能知道。

### 5.5 v5 实验的预期观察点

跑完实验后，重点关注以下信号：

| 观察点 | 预期 | 如果不符合预期 |
|---|---|---|
| [1] 的 avg_structural_entropy | **> 0**（这是 v5 修复的核心验证） | 检查 `build_physical_nodes_from_graphrag` 的 anchor 逻辑 |
| [1] 的 entropy_by_level | Level 0 最高，逐层递减 | 退火曲线可能需要调参 |
| [0] vs [2] 的社区数 | [2] 应显著少于 [0]（加边后连通性增强，合并更充分） | EdgeSchedule 权重可能太低 |
| [3] vs [0] 的 MRR | 应有 > 5% 的改善 | 核心假设可能不成立 |
| [3] vs Naive RAG 的 MRR | 目标：缩小到 20% 以内（从当前 44% 差距） | 需要根本性的方法调整 |
| [4] vs [3] 的指标 | Path A 应有正向增益（v5 图不再碎片化） | Path A 权重 0.5 可能仍然太低 |
| inference_query 的 Recall@5 | 应优于 Naive RAG 的 0.3475 | 图方法在推理场景的优势未兑现 |
