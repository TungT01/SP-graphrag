# 问题分解树

## 根问题

**如何设计一种在语义聚合过程中保持微观事实物理完整性的 GraphRAG 框架，使其在专业领域知识检索中同时具备全局导航能力和原子级溯源精度？**

---

## 子问题 P0（核心优先级）

### SP1: 物理锚定机制设计 [P0]

**问题陈述：** 如何在命题级知识图谱中为每个三元组证据建立并维护不可丢失的物理出处坐标？

**可证伪性：** 如果物理锚定机制有效，那么经过多轮图结构变换（社区合并、层级压缩）后，任意一个三元组仍可在 O(1) 时间内追溯到其原始 Chunk_ID。若存在三元组在变换后丢失出处信息，则该机制失败。

**研究方法：** 实证（系统设计 + 算法分析）

**依赖关系：** 无前置依赖，是整个框架的基础组件

**潜在风险：** 物理标识符的存储和传播可能引入额外的内存开销；在实体合并（Entity Merging）阶段，多源实体的物理锚可能产生冲突

**子任务：**
- SP1.1: 定义物理标识符的数据结构（Chunk_ID, Section_ID, Document_ID 三级锚点）
- SP1.2: 设计命题转换（Proposition Transfer）过程中锚点的继承规则
- SP1.3: 设计实体合并时多源锚点的冲突解决策略（保留所有来源 vs. 主来源标记）
- SP1.4: 分析锚点传播的空间复杂度

---

### SP2: 结构熵约束的退火聚类算法 [P0]

**问题陈述：** 如何修改 Leiden 聚类的目标函数，使其在聚类早期优先保护物理文档结构的完整性，在后期逐步释放跨文档的语义关联能力？

**可证伪性：** 如果退火聚类有效，那么在 λ 较大（早期）时，同一文档章节内的节点应高概率聚入同一社区；在 λ 衰减至 0（后期）时，聚类结果应收敛到标准 Leiden 的纯语义社区。若两端行为与预期不符，则目标函数设计存在问题。

**研究方法：** 理论分析 + 实证验证

**依赖关系：** 依赖 SP1（需要物理锚信息来计算结构熵 H_structure）

**潜在风险：** 
- λ 的退火速率选择对结果敏感，可能存在不稳定区间
- 结构熵 H_structure 的定义需要严格的信息论基础
- 目标函数 J = Q_Leiden − λ·H_structure 的非凸性可能导致局部最优

**子任务：**
- SP2.1: 形式化定义结构熵 H_structure（基于物理锚点的分布熵）
- SP2.2: 证明目标函数 J 的基本性质（有界性、λ=0 时退化为标准 Leiden）
- SP2.3: 设计 λ 的退火策略（线性衰减 / 指数衰减 / 自适应衰减）
- SP2.4: 分析算法的时间复杂度与收敛性

---

## 子问题 P1（重要优先级）

### SP3: 去标签化 U 型双轨检索策略 [P1]

**问题陈述：** 如何在不依赖昂贵领域标签的前提下，设计从宏观社区导航到微观原始文本块精确调用的高保真检索路径？

**可证伪性：** 如果 U 型检索有效，那么在给定一个需要全局理解的查询时，系统应能（a）通过自上而下路径定位到正确的社区范围，且（b）通过自下而上路径以 ≥95% 的准确率调用到包含答案的原始文本块。若任一路径的准确率显著低于基线，则策略失败。

**研究方法：** 实证（系统设计 + 对比实验）

**依赖关系：** 依赖 SP1（物理锚提供自下而上路径）和 SP2（层级社区结构提供自上而下路径）

**潜在风险：** 双轨融合策略的设计（如何合并两条路径的检索结果）可能是工程瓶颈

**子任务：**
- SP3.1: 设计自上而下路径：查询→层级社区摘要匹配→范围锁定
- SP3.2: 设计自下而上路径：查询→节点语义匹配→物理锚追溯→原始 Chunk 调用
- SP3.3: 设计双轨融合策略（分数加权 / 级联过滤 / 交集优先）
- SP3.4: 分析检索延迟与传统方法的对比

---

### SP4: 低成本工程路径 [P1]

**问题陈述：** 如何通过修改底层算法目标函数（而非增加 LLM 预处理调用）来实现高精度 GraphRAG，从而控制计算成本？

**可证伪性：** 如果低成本路径有效，那么 PhysAnchor-GraphRAG 的总 LLM 调用次数应不超过标准 GraphRAG 的 1.1 倍，同时在溯源精度上显著优于后者。若 LLM 调用成本大幅上升，则成本优势不成立。

**研究方法：** 实证（成本分析 + 对比实验）

**依赖关系：** 依赖 SP1-SP3 的完整实现

**潜在风险：** 物理锚的维护可能在极大规模图上引入非 LLM 的计算开销

**子任务：**
- SP4.1: 分析框架各阶段的 LLM 调用次数（与 GraphRAG、MedGraphRAG 对比）
- SP4.2: 评估物理锚存储和传播的额外计算开销
- SP4.3: 设计可选的"轻量模式"（在精度可接受范围内进一步降低开销）

---

## 子问题 P2（拓展优先级）

### SP5: 跨领域泛化性 [P2]

**问题陈述：** PhysAnchor-GraphRAG 框架在不同专业领域（科研文献、医疗文本、法律文书）间的泛化能力如何？

**可证伪性：** 如果框架具有泛化性，那么在无需领域特定调优的情况下，框架在至少两个不同领域的数据集上均应优于领域无关的 GraphRAG 基线。

**研究方法：** 实证

**依赖关系：** 依赖 SP1-SP4 的完整框架

**子任务：**
- SP5.1: 选择 2-3 个不同领域的评测数据集
- SP5.2: 设计领域无关的评测指标
- SP5.3: 分析框架在不同领域间性能差异的原因

---

## 依赖关系图

```
SP1 (物理锚定) ──→ SP2 (退火聚类) ──→ SP3 (U型检索) ──→ SP4 (成本分析)
       │                                       │                    │
       └───────────────────────────────────────→└──→ SP5 (泛化性) ←─┘
```

SP1 是基石；SP2 依赖 SP1 的锚点信息；SP3 依赖 SP1+SP2 的完整索引结构；SP4 和 SP5 是全框架的评估维度。
