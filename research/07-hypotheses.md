# 研究假设

基于 Gap 分析（06-synthesis-gap.md）、问题分解树（02-problem-tree.md）和用户反馈修订。

---

## 核心对比优势声明

本研究的价值主张通过两个对比场景来界定：

**对比场景 A — PhysAnchor-GraphRAG vs. 直接方案（Naive Full-Context）**

所谓"直接方案"是指将原始文档逐句/逐段直接输入 LLM 进行问答，不经过任何索引或图结构化处理。直接方案在微观事实问题（如"某实验的具体剂量是多少？"）上通常能达到很高的准确率，因为 LLM 直接阅读了原始文本。但其成本随文档规模线性增长，在大规模语料上不可承受。

**核心假设 A**：PhysAnchor-GraphRAG 可以在微观事实问题的回答准确率上接近直接方案（差距 ≤ 5%），同时将 LLM token 消耗降低一个数量级以上。

**对比场景 B — PhysAnchor-GraphRAG vs. 原版 GraphRAG**

原版 GraphRAG 通过 Leiden 社区层级和社区摘要在宏观问题（如"该领域的主要研究趋势是什么？"）上表现优异，但其纯拓扑聚类导致微观事实的溯源链断裂，在微观问题上表现欠佳。

**核心假设 B**：PhysAnchor-GraphRAG 可以在宏观问题的回答质量（Comprehensiveness、Diversity）上与原版 GraphRAG 持平或接近，同时在微观事实问题的回答准确率和溯源精度上显著优于原版 GraphRAG。

## 技术假设

### H1: 结构熵约束退火聚类假设

**假设陈述**：在 Leiden 聚类的目标函数中引入基于物理锚点分布的香农结构熵（Shannon Structural Entropy）惩罚项 H_structure，并通过退火系数 λ 的动态衰减调度，可以生成"物理结构感知"的社区划分——在聚类早期优先保护同一文档章节内节点的聚类一致性，在后期逐步释放跨文档的语义连接能力。

**形式化**：

目标函数 J = Q_Leiden − λ(t)·H_structure

其中 H_structure 采用香农熵定义：对于聚类结果中的每个社区 C_k，计算其内部节点所来源的文档章节（Section）的分布熵：

H_structure = Σ_k (|C_k|/N) · H(P_k)

其中 P_k 是社区 C_k 中节点的 Section_ID 分布概率向量，H(P_k) = −Σ_i p_i·log(p_i) 为其香农熵。H_structure 越大表示社区内来自不同章节的节点越混杂，越小表示社区内节点的物理来源越一致。

λ(t) 为退火调度函数（初步选用指数衰减 λ(t) = λ₀·e^{-αt}）。

**关键性质**：
- 当 λ → 0 时，J 退化为标准 Leiden 目标函数 Q_Leiden（边界条件保证）
- 当 λ 较大时，优化器倾向于将同一章节的节点聚入同一社区以降低 H_structure
- λ 的衰减过程实现从"物理结构保护"到"语义自由连接"的平滑过渡

**可证伪条件**：
- 若退火聚类的模块度 Q 显著低于标准 Leiden（差距 > 5%），则香农结构熵约束与模块度优化存在不可调和的冲突
- 若 λ = 0 时的结果与标准 Leiden 不一致，则目标函数的退化性质不成立
- 若"同章节节点聚类一致性"指标不随 λ 单调变化，则退火调度机制失效

**对应 Gap**：Gap 1（Leiden 目标函数缺乏物理结构约束）

**关联子问题**：SP2

### H2: 物理锚定溯源完整性假设

**假设陈述**：通过为知识图谱中每个三元组挂载 (Chunk_ID, Section_ID, Document_ID) 三级物理锚点，并在实体合并阶段保留所有来源锚点，可以实现经过多轮图结构变换（社区合并、层级压缩）后，任意三元组仍能在 O(1) 时间内追溯到其原始文本块。

**设计要点**：物理锚是元数据挂载操作（类似于数据库外键），不增加 LLM 调用，不引入新的图节点，对图的拓扑结构无影响。

**可证伪条件**：
- 若存在三元组在经过实体合并或社区压缩后丢失物理锚信息，则锚点传播规则存在漏洞
- 若锚点存储的额外空间开销超过原始图规模的 50%，则轻量化假设不成立

**对应 Gap**：Gap 2（三元组缺乏不可丢失的物理出处坐标）

**关联子问题**：SP1

### H3: 微观问题准确率假设（对应对比场景 A）

**假设陈述**：在微观事实问题（需要精确定位到原始文本中特定事实的问题）上，PhysAnchor-GraphRAG 的回答准确率可以接近直接方案（将全部原始文本逐段输入 LLM），准确率差距 ≤ 5%。同时，PhysAnchor-GraphRAG 的 LLM token 消耗应比直接方案降低至少一个数量级（≥ 10x）。

**核心逻辑**：物理锚定机制确保了微观事实到原始文本块的精确追溯，使检索阶段能够精准调用包含答案的原始 Chunk 而非依赖经过多层压缩的社区摘要。这使得系统在微观问题上"几乎等效于直接阅读原文"，但通过图索引和层级检索大幅减少了需要输入 LLM 的文本量。

**可证伪条件**：
- 若微观准确率与直接方案差距 > 10%，则物理锚的溯源精度不足以支撑微观事实的精确检索
- 若 token 消耗降低不足 5x，则图索引和检索策略的压缩效率不够

**关联子问题**：SP1, SP3, SP4

---

### H4: 宏观-微观均衡假设（对应对比场景 B）

**假设陈述**：相较于原版 GraphRAG，PhysAnchor-GraphRAG 在宏观问题（需要跨文档全局理解的问题）的回答质量上与之持平或接近（Comprehensiveness 和 Diversity 差距 ≤ 5%），同时在微观事实问题的回答准确率上显著优于原版 GraphRAG（提升 ≥ 15%）。

**核心逻辑**：退火聚类在后期（λ→0）收敛到接近标准 Leiden 的语义社区，因此宏观能力不受显著影响；而物理锚定和退火聚类早期的结构保护确保了微观事实的溯源链不断裂，提升微观问题的回答能力。

**可证伪条件**：
- 若宏观问题的 Comprehensiveness 下降 > 5%，则退火聚类对社区语义结构的干扰过大
- 若微观问题准确率提升 < 10%，则物理锚定和结构熵约束对微观事实保护的效果不显著

**关联子问题**：SP2, SP3

## 辅助假设

### H5: λ 退火调度收敛性假设

**假设陈述**：存在一类退火调度函数 λ(t)（初步选用指数衰减 λ(t) = λ₀·e^{-αt}），使得退火聚类算法在有限步内收敛到稳定的社区划分，且最终划分的综合质量（兼顾模块度 Q 和章节一致性）优于固定 λ 的静态约束方案。

**可证伪条件**：
- 若算法在合理迭代次数内不收敛，则目标函数的非凸性导致退火策略不可用
- 若固定 λ 的静态方案在多数数据集上效果相当或更优，则退火调度不具有实际价值

**关联子问题**：SP2

---

### H6: 跨领域泛化假设

**假设陈述**：PhysAnchor-GraphRAG 在至少两个不同专业领域的数据集上，无需领域特定调优，均能在微观问题上优于原版 GraphRAG。

**可证伪条件**：
- 若在某领域上退火聚类的效果不如标准 Leiden，则该领域的文档物理结构不具有预期的语义信号价值
- 若不同领域需要显著不同的 λ 退火策略才能达到最优，则框架的"领域无关"主张受限

**关联子问题**：SP5

## 创新点与非创新点的边界澄清

### 本研究的两个核心创新

**创新 1：命题转换与物理锚定机制（Proposition Transfer & Physical Anchoring）** — 为 KG 三元组挂载三级物理出处坐标，并在图结构演化中保持溯源不丢失。这是贯穿全框架的基础机制，对应 H2。

**创新 2：结构熵约束的退火聚类算法（Structure-Entropy-Constrained Annealing Clustering）** — 修改 Leiden 目标函数 J = Q_Leiden − λ·H_structure（H_structure 采用香农熵），通过 λ 退火实现物理结构保护到语义自由连接的平滑过渡。这是核心算法创新，对应 H1。

### 非创新的工程集成

**U 型双轨检索策略** — 自上而下（社区摘要导航）+ 自下而上（物理锚追溯）的检索策略直接借鉴了 MedGraphRAG (L3) 的 U-Retrieval 和 HiRAG (L13) 的层级检索等已有方法。本研究在检索策略设计上的工作属于对已有方法的工程集成与适配，不声称检索策略本身为创新贡献。其价值在于：通过物理锚定为自下而上路径提供了精确的追溯终点，使已有的 U 型检索范式获得了更高的微观溯源精度。

## 假设间依赖关系

```
H2 (物理锚定) ──→ H1 (退火聚类需要锚信息计算 H_structure)
      │                     │
      │              H5 (λ收敛性保障 H1)
      │                     │
      ↓                     ↓
H3 (微观准确率 ≈ 直接方案)  H4 (宏观持平 + 微观提升 vs. GraphRAG)
                             │
                             ↓
                          H6 (跨领域泛化)
```

H2 是基石假设——物理锚定是一切的基础。H1 依赖 H2 提供的锚信息来计算 H_structure。H3 和 H4 是两个核心对比场景的操作化假设。H5 保障 H1 的算法可行性。H6 是泛化性验证。
